# S8 之后的下一波优化设计

日期：2026-09-30。对照代码：R12 `b864c51`；结果归档：`fbaf2ca` / S8。本文是下一波方案与验收边界，尚未实施，不表示已获得新的性能收益。

## 目标和已有证据

目标是在保留 R12 精度和主要收益的基础上，改变通用路径的数据流，并逐步覆盖固定开销明显的输入。继续满足一次调用恰好一个 kernel launch；线上只修改 kernel.asc 或自建 .asc/.h；由真实 shape、dtype、布局与资源生成并选择方案，不按测试点号分派。主机逻辑检查后直接交线上验证，不把本地 NPU 矩阵或 profiling 作为前置条件。

S8 的关键证据：

- 点 13：214.07→37.38 μs，快 5.73 倍，强烈支持旧版最终 Sum 的显著成本。剩余耗时不是新 Sum 的单独计时，不能断言继续改 Sum 就能达到 5.14 μs。
- 点 8–12：下降 13.78%～37.65%，证明本轮收益覆盖多个点。点 12 已为最优的 1.54 倍，需要特别保护。
- 点 5/6：+8.00%/+7.25%，补偿树的固定成本是待检验解释，尚未确认短 M 或实际路径。
- 点 1–4、7、14–15：未出现同等级明显收益。点 15 仍距最优 27.43 倍，不能继续预设它与点 13 是相同瓶颈。

所有点的具体 B/M/N/K、dtype、布局仍未知；不据这些数字编造官方 shape。没有完整评分公式，不按总耗时下降估算名次。

## 路线比较与推进顺序

| 路线 | 具体改动 | 收益来源及代价 | 建议 |
| --- | --- | --- | --- |
| 继续调整最终 Sum | 无须建树时直接合并；比较短归约与补偿树成本 | 改动小，可处理新增固定成本；难以解释全部剩余差距 | 同波独立小候选，不与融合版本混改 |
| 按行块逐块融合 Matmul→Max | 核组拥有一段行和一个 N 区间，只保存有界 C 临时块与行最大值 | 缩短完整 similarity 生命周期；要处理分工、尾部和缓冲复用 | **下一正式版本主线** |
| 直接重写底层 Cube | 自管 LoadData/Mmad/Fixpipe、布局及同步 | 有望减少小矩阵的库调度成本，开发和精度风险也更大 | 后续独立算法族，不与首次融合同时重写 |

先交付可以独立比较的逐块融合版，再根据线上响应选择异步流水、短归约或精简 Cube 路径。方案按阶段推进，每次正式版本都保留单独的全 15 点结果；不预先承诺倍率或第一梯队排名。

## 主线第一步：拥有行块，逐块完成 Max

当前路径：

```text
全部 Matmul → 完整 S 写 GM → 全核同步
    → 全部 Max(N) → 行最大值写 GM → 全核同步 → R12 Sum(M)
```

拟议路径中，一个任务负责 `(batch, M 行块, N 分片)`：

```text
初始化该任务的行最大值
    → 逐个 N 块：完整 K 点积 → 有界 C 临时块 → 更新行最大值
    → 写出这一行块的部分最大值

N 没有分片：一次全核同步 → R12 Sum(M)
N 有多个分片：同步 → 并行合并同一行的部分 Max → 同步 → R12 Sum(M)
```

先沿 B/M 提供任务；并行度不足时才生成 N 分片候选。同一行各个 N 分片只能先做 Max 合并，完成整行后才能进入 M 求和。第一版保留完整行最大值数组及 R12 求和方式，不同时改为每个任务输出部分 Sum，以免混入第二次加法顺序改动。

拆分依据来自算子代数：B 独立；M 行块在完成全 N 后可求和；N 分片产生的是每行最大值向量；跨核拆 K 必须先合并完整部分点积再 Max，通信量较大，本波不作为首选。

### 首版沿用已使用的 Matmul 接口

采用当前 `Matmul + IterateAll` 的同步模式，将 C 写入每个活跃核组独占的可复用 GM 块，然后立即在 Vector 上归约。输入继续使用原始物理跨度；输出 C 的行距与完整输入 B 的 N 分开设置。这样先改变所有权和生命周期，避免同时引入 LocalTensor 输出的迭代格式以及异步状态机。

这是有界 GM 中转，**不能宣称消除了全部 C 的 GM 读写**。逻辑上仍可能写读 O(BMN) 个中间元素；预期价值是更小的工作集、更短的生产消费间隔、N 不分片时少一次全核阶段同步，以及为后续重叠建立结构。缓存和耗时收益需线上验证；逐块 Vector 处理也可能增加 Cube 等待。

设 N 分片数为 S、活跃核组数为 P、临时块为 Tm×Tn：

- 当前显式 scratch 约为 `4*B*M*align16(N) + 4*B*align32(M)` 字节。
- 新路径约为 `4*P*Tm*align16(Tn) + 4*B*S*align32(M)`；S>1 时另需最终行最大值数组，S=1 时直接使用同一个数组。
- 以上均另计 Matmul 系统 workspace、对齐和必要的保护空间。第一版单缓冲，异步版再按实际缓冲数计费。

每个输出行区间及分片区间独占其写入的 32 字节块，尾部显式填充，不能让两个任务共享一个写回块。最大值 padding 使用负无穷或合法负哨兵；求和 padding 使用零。

### 规划器新增的是执行方式

在已有规则生成基础上增加：算法族、行块范围、N 分片数、每核任务数、块缓冲尺寸、部分最大值空间及归约阶段数。外层任务范围和 SDK 的 baseM/baseN/baseK 分别记录。

候选生成来自维度、现有 tile 与核数：保留 S=1，围绕补足并行度所需的分片数生成邻近候选，并限制 S 不超过非空 N 块数。比较每核实际分到的 Matmul 块数、最大负载和尾轮；不能只看活跃核数。例如增加分片形成第二轮，可能比略少核的一轮更慢。

先按真实资源、地址边界和 SDK tiling 接受情况排除非法方案，再用上述结构成本选择。模型尚未校准为时间，不能声称已预测最佳路径；R12 通用实现保留为合法回退。新路径按普适规则默认参与选择，不把所有输入都留在旧路径等待本地 NPU 测量。

### 同步与缓冲的明确边界

- 一个结果块必须完成全部 K 累加后才能 Max；不得对 K 的部分结果先取最大值。
- 同步 IterateAll 完成后才能读 C。下次 Cube 写回同一 GM 块前，前一次 MTE2 读取必须完成；不能仅因 Vector 队列已 DeQue 就认定 Scalar 发起的下一次 Matmul 不会覆盖该块。实现时显式建立对应完成依赖。
- 有界 C 缓冲按核组独占；部分 Max 按任务区间独占；全局合并前所有相关写回完成。
- 第一版保留 MIX 1:1 的参与者约定；AIC 运行 Matmul server，不能把它错误地加入 AIV 全核屏障。空闲 AIV 仍参与必须的屏障。
- N 分片模式允许保留两次全局屏障，不以减少屏障数量牺牲并行度或正确性。
- 全部选择和 SDK 回退在 launch 前完成。启动后失败不能再启动旧 kernel 补算。

## 主线第二步：生产消费重叠与输入复用

在上述结构获得独立线上结果后，再引入双缓冲：Cube 生产第 t+1 块时，Vector 归约第 t 块；两个缓冲各自记录可写、完成和消费结束状态。明确排空最后一块，并覆盖只有一个块、奇数块、尾块以及任务切换。

优先沿用 GM 块布局研究 `IterateAll<false>` 与 `WaitIterateAll`；正确性依赖不靠队列深度从 1 改为 2 自动解决。需要重新核算通信、GM、UB 和事件资源；异步接口可用不表示收益自动成立。

若后续切换 `Iterate/GetTensorC` 的 LocalTensor 消费形式，应作为另一个可比较方案。CANN 9.0 文档对异步 VECIN 输出格式有 NZ 约束，归约布局也必须一起改变；910B 上 LocalTensor 接口不等于硬件完全绕过 GM。

行块沿 N 连续处理提供了复用 A 的机会，但“任务连续”不等于“L1 已保留 A”。先研究任务遍历顺序和内层 tiling，再在 SDK 明确支持的机制或低阶实现中固定复用；不把调度意图写成已经减少的输入流量。

## 独立支线：控制短归约与小矩阵的固定成本

短归约先处理有确定结构依据的情况：M≤8 时当前树没有任何向量合并层，可直接合并真实元素，跳过残差初始化和无用同步；没有最终输出任务的 AIV，在最后一个必须参与的屏障之后可以跳过求和缓冲准备。两项都应单独检查事件和输出所有权。

更宽的 Scalar/Vector 分界作为实验参数，由真实 M、输出任务数和资源生成候选；不能把点 5/6 自动认定为 M≤8，不能从 API 数直接推算最佳阈值。保留强抵消与跨块补偿，不用普通树形求和绕过误差问题。这条支线与逐块融合分开提交，以便判断能否缓解 S8 新增退化。

对于点 1–5、7、14–15 等剩余差距，准备第三种算法族：**精简的 Cube+Vector 融合路径**，补齐当前“小规模纯 Vector / 通用 Matmul server”的空档。它必须真正减少启动、调度和同步成本，不只是增加若干 tile。只有当后续线上响应仍指向固定流程时再进入低阶 Mmad/LoadData/Fixpipe 设计，保留 FP32 精度、四布局和尾块支持边界。

## 实施边界与验证目标

预计涉及 kernel.asc 的 host 分派、临时空间及新 MIX 路径，matmul_plan.h 的所有权/分片规划，以及已有 runner/plan metadata 对新算法族的记录。设备算法可放在新增 .asc，纯规划描述与接口放在 .h；线上仍只复制这些允许修改的源码。

流式路径不再返回完整 similarity 给本地 runner，必须如实记录 `similarity_available=false`；不能为回读诊断保留完整 S 或额外启动 kernel。旧路径继续允许原中间结果诊断。报告按输入身份和实际计划关联，历史 schema 继续可读。

主机检查集中在可证的逻辑：

- 规则生成 B/M/N/K 的对齐边界、尾块、核数一轮前后、S=1 与 S>1 切换；覆盖两 dtype 与四布局。
- 每个有效输出元素有唯一 owner，任务总覆盖无缺漏，N 分片无重复/空分片；含无任务核与多轮任务复用。
- 全负、零、近似相等的 Max、跨行强抵消、长 K；使用实际存储输入的 FP64 golden，检查有限输出和重复一致。
- N 分片先 Max 后 Sum 的反例：两分片的两行最大值分别为 `[100,0]`、`[0,100]`，正确输出为 200，不能错误得到 100。
- 所有 UB/GM 空间、对齐、生命周期、整数溢出、单次 launch、SDK 拒绝后的启动前回退及新旧元数据兼容。

不新增本地 NPU 测试前置步骤。每个候选交线上后保存全部 15 点：以 S8 为首版对照，重点保护 8–13、记录 5/6，并观察 1–7、14/15 是否出现新的响应。融合无收益时区分并行度、逐块调用成本和已保留的 GM 中转；流水无收益时再考虑块粒度与复用，不能仅凭无改善排除输入类别。
