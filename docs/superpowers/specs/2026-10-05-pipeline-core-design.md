# R23 性能核心重写设计

用户已授权直接重写。目标是让物理分块、片上驻留和生产消费流水成为一个独立方案。保留 Small、FP32 Max、补偿 Sum、旧执行器及公开接口；线上每调用一次 launch；不运行本地 NPU，不改 judge/main/CMake。

## 方案

新增纯 host `pipeline_plan.h` 和 `pipeline_cube.asc`。Auto 在 Small 后、SDK 准备前，根据实际硬件容量和输入元数据生成 BM=16/32/64/128、BN=32/64/128 候选，BK<=128，选择完整资源可行的流水；显式旧 family/tile/实验开关继续原控制路径。未支持平台回退原方案。候选基于填充工作量、最重核、输入复用和归约流量的归一化模型，不使用点号或训练数据，不把模型当实测周期。

A 能驻留 L1 时跨 N 保留；否则 A 与 B 均按 K 双缓冲。L0A/B 双缓冲，L0C 双缓冲，使 MTE2/LoadData/Mmad/Fixpipe 分别按资源代际同步。GM 的两槽 FREE 等待推迟到发布前，允许 Cube 在消费者忙时先完成下一块。AIV 双 UB 队列预取下一行条带，复用已验证 Max/Sum。两端持续跨 owner，不逐任务排空。

任意 M/N/K 尾部通过 L1 NZ 清零和有效尺寸 ND2NZ 拷入得到完整 16 元素分形，经典 LoadData/Mmad 只使用补齐维度；Fixpipe 写完整物理 tile 到有界槽，Max 只消费有效行列。四转置和两 dtype 保持。L1 尾零必须先等前一代 LoadData 结束，不依赖未承诺的 N 方向隐式填充。

## 验证与边界

纯 CPU 测试覆盖资源规划、四布局物理存储及尾零、跨批次驻留、数值和标志生命周期，真实 host 的无 SDK 准备与单 launch，流水两端所有权和归约。不能代替 CANN 编译或真实硬件同步。默认启用新主干，无错误后重试第二次 launch；线上错误时可在编译期关闭新路径恢复参考。未包含两 AIV 或直接 L0C→UB，避免将两种额外架构一起引入。
