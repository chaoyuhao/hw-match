# R13 Streaming Matmul→Max Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Replace the generic full-similarity lifecycle with bounded per-core C scratch and row-owned streaming Max.

**Architecture:** Keep the existing SDK-selected Matmul tile, full K and MIX 1:1. Select nonempty N shards by exact per-core Matmul-call load, reduce C immediately, merge shard maxima when necessary, then call the unchanged R12 Sum. Preserve forced GM and Small paths and truthful local metadata.

**Tech Stack:** C++14, Ascend C / CANN 9.0 target, Python unittest, CPU behavioral test doubles.

**Spec:** ../specs/2026-09-30-next-wave-optimization-design.md

## Global Constraints

- Exactly one kernel launch per invocation; all decisions precede launch.
- Online edits are kernel.asc and new .asc/.h only; no runtime diagnostics in online code.
- No local NPU testing prerequisite. CPU checks do not prove CANN compilation or hardware synchronization.
- Keep Small dispatch and R12 compensated Sum semantics unchanged.
- Use real dimensions/layout/resources; no official-point identities.

## Review Focus

- Reusable C storage must wait for MTE2 before the next Cube write (device helper and event-order checks).
- N fragments must merge Max before Sum (cross-shard counterexample in device-helper tests).
- Tail row writes must own entire 32-byte blocks (guarded GM tests).
- Huge batch counts must not cause planner loops proportional to batches (planner overflow/large-B tests).
- Stream scratch must never be read as full similarity (runner and metadata tests).
