目标：在已通过环境小测试的 910B2C / CANN 9.1.0 镜像上，提供可编译、可运行、可逐项验证的 BatchMatmulMaxSum 候选实现。开发工作区没有 CANN/NPU，实际编译和设备精度状态必须单独报告。

依据：[赛题 README](../README.md)、[已讨论的两阶段方案](BASELINE_RESEARCH.md)。比赛以 CANN 9.0.0 线上评测为准。

## 设计

- `kernel.asc` 保留官方 `run_kernel` ABI。使用 Cube Matmul 高阶 API，FP16/BF16 输入和 FP32 中间结果；直接按输入存储布局寻址，支持四种转置组合。
- 按 batch/M/N 分配不重叠任务，K 不跨核拆分。中间矩阵的行跨度补齐至 16 个 FP32 元素，避免相邻任务写入共享的非对齐块。
- 第二个 Vector kernel 分块读取每一行，仅对有效 N 元素归约；按固定顺序累加有效 M 行。精确写回 B 个 FP32，包含不足 32 字节的输出。
- 首版在 host 分配临时 GM，并在释放前同步 stream。中间矩阵、分配与同步带来额外开销，这是本地正确性版本，不宣称可直接参赛或性能达标。
- 参数化本地 runner 调用同一实现；每次初始化输出为 NaN，支持重复执行、输入只读校验，以及导出真实 Matmul 中间矩阵。
- Python 用量化后实际输入的 FP64 Matmul 生成 golden，验证长度、有限性、`rtol=atol=1e-4` 和重复执行一致性。报告固定标记 `ONLINE_EVALUATION=NOT_RUN`。

## 实施与验证

1. 先编写测试，验证已知值、四种物理布局、量化后 golden、错误长度/NaN 的拒绝以及执行失败传播，再实现本地数据与验证工具。
2. 实现 Cube + Vector kernel 和本地 runner。默认小用例覆盖两 dtype × 四布局、负值、尾块、batch；扩展用例覆盖长 K、大 M/N、跨多核任务循环。
3. 增加一键构建运行入口，输出独立日志、源码摘要及每个 case 的精度结果；保留失败用例供复现。
4. 运行本工作区可执行的全部测试、shell 语法检查及代码审查；提交并同步 GitHub。真实 CANN 编译与 NPU 测试须在用户镜像执行，不以模拟测试替代。

## 审查重点

- 转置下的起始地址与原矩阵跨度是否一致。
- Matmul 尾块、输出 padding、跨核写入是否越界或重叠。
- 临时空间是否保持到设备完成，ACL 错误是否变为失败退出。
- 负值、N=1、B=1、非对齐输出和多次调用是否正确。
- 验证器是否会接受旧输出、缺失输出、NaN、超时或不匹配的结果。
